## Friction Points

1. **No Bash tool in Atlas context.** Forge is responsible for git commits per convention, but Atlas was running the full pipeline as one agent instance. The commit could not be executed. This is a recurring blocker when Atlas acts as Forge-proxy.

2. **Sentinel outbox still had [PENDING] from plan-1.** Should have been marked [ROUTED] at close of plan-1 cycle. Was cleaned up at start of this cycle but represents a gap in cycle-close discipline.

3. **Forge inbox item count.** The inbox now has 3 items (two plan-1 era, one new plan-2). Not at the ~10 threshold yet, but the "stale items at the top" pattern means Forge must scroll past completed work to find actionable tasks. The new inbox archiving guidance (just added to atlas.md) will address this once it accumulates.

## Proposed Improvements

1. **atlas.md or Kernel — Forge commit proxy rule:** When Atlas is running the full pipeline without a separate Bash-capable Forge invocation, add a protocol for Atlas to note the commit message to be run and mark it as a pending manual step for CJ. Currently this just silently fails to commit.

2. **cycle-close checklist:** Add a short checklist to atlas.md that Atlas runs at cycle close: (a) mark all agent outboxes [ROUTED], (b) verify Forge committed, (c) write retro, (d) update improvements.md. This prevents the [PENDING] leak seen in friction point 2.
